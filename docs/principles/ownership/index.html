계층과 소유권

Tokens, Foundation, Primitives, Compositions의 단방향 책임을 정의합니다.

이 문서는 현재 Core 의존 규칙과 선택적 Capability의 진입 조건을 구분한다. 구현 정본은 package manifest, eslint.config.mjs, eslint-rules/와 architecture contract test이며 문서는 실행 가능한 경계를 설명한다.

공통 원칙:

  • 앱과 다른 package는 public exports만 사용한다.
  • headless/vendor type, instance와 경로를 public API에 노출하지 않는다.
  • package끼리 source deep import하지 않는다.
  • Foundation은 React package dependency가 아니라 app/Storybook bootstrap의 필수 CSS prerequisite다. Primitive는 Foundation이 설치한 semantic CSS variable 계약을 전제로 한다.
  • Foundation 없이 Primitive를 사용하는 환경은 공식 지원하지 않는다. 별도 embed 환경은 최소 token CSS entry와 smoke test를 먼저 설계한다.
  • Composition은 선택적 Capability dependency를 끌어오지 않는다.
  • 디자인 시스템에서 apps/**, next/*, API, Query, auth, router, analytics를 import하지 않는다.
  • root barrel은 server-side module evaluation에서 browser global을 실행하지 않는다. Client-only module은 명시적인 client boundary, lazy loading과 SSR fallback 계약을 가진다.

Token 규칙

다음 값은 raw literal보다 semantic token을 사용한다.

  • color와 contrast pair
  • spacing과 size scale
  • radius와 elevation
  • z-index와 overlay level
  • duration, easing과 motion preference
  • typography role

현재 ds/no-hardcoded-color, ds/no-arbitrary-zindex, ds/no-raw-transition이 JavaScript/TypeScript/JSX의 주요 drift를 차단한다. raw CSS와 vendor runtime adapter도 같은 의미 계약을 review에서 확인한다.

모션과 애니메이션 규칙

JLCA는 **절제된 기능적 모션(quiet functional motion)**을 사용한다. 모션의 목적은 화면을 꾸미는 것이 아니라 상태 변화, 입력 결과와 공간 관계를 빠르게 설명하는 것이다. 아기자기한 bounce, 과장된 overshoot, 반복 장식과 시선을 빼앗는 연출은 사용하지 않는다.

  • Primitive는 hover, pressed, checked, open/closed처럼 자신이 소유한 UI 상태의 모션을 함께 소유한다. 별도의 범용 Animation 컴포넌트나 application animation service를 만들지 않는다.
  • duration과 easing은 @jaeilnet/design-tokens의 motion token을 사용한다. component source에 150ms, duration-200 또는 임의 cubic-bezier를 직접 추가하지 않는다.
  • 기본 피드백은 duration.fast, 일반 상태 전환은 duration.base 안에서 끝낸다. duration.slow는 Switch thumb처럼 공간 이동을 읽어야 하는 제한된 경우에만 사용한다.
  • 기본 easing은 감속형 ease.standard다. spring은 bounce나 overshoot가 없는 경우에만 허용하며, 귀엽거나 탄성적인 인상을 만드는 spring은 사용하지 않는다.
  • 성능과 시각적 안정성을 위해 transform, opacity, color, background-color, border-color, box-shadow를 우선한다. top, left, width, height, margin, padding처럼 매 프레임 layout과 주변 콘텐츠 배치를 다시 계산하는 속성은 일반 transition 대상으로 삼지 않는다.
  • transform을 사용하더라도 주변 레이아웃 공간은 최종 크기로 먼저 확보한다. 오류·도움말·로딩 콘텐츠는 필요한 공간을 예약하거나 overlay/portal로 분리하여 등장할 때 형제 요소를 밀지 않는다.
  • 동시에 여러 요소를 순차적으로 튀게 하는 stagger, 무한 반복과 큰 거리 이동은 기본 컴포넌트에서 금지한다. 지속 모션은 진행 중임을 알려야 하는 spinner, progress, skeleton처럼 실제 상태가 있는 경우로 제한한다.
  • prefers-reduced-motion: reduce에서는 의미와 조작 가능성을 보존한 채 이동과 반복을 제거하고 상태를 즉시 또는 거의 즉시 전환한다.
  • Storybook과 테스트는 최소한 default/active/disabled/open 상태, reduced-motion 계약과 애니메이션 중 layout shift가 없는 구조를 검증한다. 수동 검토는 저사양 모바일 기준으로 끊김, 긴 main-thread 작업과 불필요한 repaint가 없는지 확인한다.

권장 인상은 “통통 튀는 재미”가 아니라 눌렀다는 감각은 분명하지만 화면은 흔들리지 않는 단단한 반응이다. 예를 들어 Checkbox는 색과 check 표시를 짧게 전환하고, Switch는 track 색과 thumb 위치만 이동하며, Select는 이미 확보된 trigger를 유지한 채 portal content의 opacity와 작은 transform만 전환한다.

Public surface

Form Controls와 validation adapter의 public catalog, callback 예시, 접근성·모션 계약은 Form Controls에 정리한다.

생성 조건을 통과한 경우에만 추가하는 CONDITIONAL CAPABILITY:

각 package root는 안정된 소비자 API만 공개한다. CSS side effect가 필요하면 styles.css처럼 이름이 드러나는 좁은 export를 사용한다. root barrel을 import하는 것만으로 Chart, Carousel, Map runtime/CSS가 설치되어서는 안 된다.

Web 의미론 계열 규칙

  • Core family는 외부 library의 catalog가 아니라 Layout, Typography, Form, Table, Navigation, Media, Document Structure, Interactive Content라는 Web 의미 체계에서 책임을 정한다.
  • 후보 family 이름은 public component나 API 승인을 뜻하지 않는다. 구현됨 상태는 native semantics, token/style ownership, 접근성, SSR, type, Story, 문서와 dependency gate를 모두 닫은 뒤에만 부여한다.
  • native HTML element가 요구를 표현하면 ARIA role로 다시 만들지 않는다. ARIA composite widget은 native model로 표현할 수 없는 interaction과 keyboard 계약이 승인된 경우에만 설계한다.

Table은 static tabular data의 native structure를 소유한다. 좁은 viewport에서도 table, thead, tbody, tfoot, tr, th, td의 display를 block/grid/flex로 바꾸거나 행을 card로 변환하지 않는다. overflow는 이름 있는 opt-in TableScrollArea가 소유하며, Table 자체는 wrapper, grid role, selection, editing, sorting state와 cell keyboard navigation을 만들지 않는다. interactive DataGrid는 Table prop 확장이 아니라 별도 설계다.

Storybook 순수성

디자인 시스템 Story는 다음 없이 렌더되어야 한다.

  • direct fetch, XHR, WebSocket, EventSource
  • app QueryClient, generated API, auth/router provider
  • environment secret
  • 제품 Domain fixture import

local fixture와 action callback으로 light/dark, interaction, error/empty/disabled 상태를 표현한다. theme·locale처럼 안정된 UI 환경 decorator는 허용하지만 application service를 숨기지 않는다.

각 공개 component는 usage·non-usage, 상태 matrix, theme·viewport, keyboard play test, 접근성 주의와 Composition 예시를 제공한다.

반응형 Layout 규칙

  • RepeatGrid.columns, Grid.columns, GridItem.span은 scalar base와 별도 responsive override를 사용한다.
  • breakpoint는 mobile → mobile.s → tablet → laptop → laptop.lg → laptop.xl의 mobile-first min-width 순서다.
  • dotted token은 Tailwind variant에서 hyphen으로 바꾼다: mobile.s → mobile-s:, laptop.lg → laptop-lg:, laptop.xl → laptop-xl:.
  • Tailwind source detection을 위해 가능한 모든 1–12 조합은 package-private 완전 literal map에 존재해야 한다. class fragment를 런타임에 결합하지 않는다.
  • responsive spacing, Flex/Stack/Group 속성, offset, order, row span과 임의 template은 아직 공개 계약이 아니다.

Vendor 예외

Vendor가 raw runtime 값을 요구해도 가능한 한 token을 adapter에서 해석한다.

  1. Chart.js 색은 CSS custom property 또는 typed token에서 읽는다.
  2. Maps SDK의 marker HTML/JS option도 semantic role에서 값을 얻는다.
  3. Carousel global CSS는 Carousel package의 명시적 style entry로만 노출한다.
  4. Radix portal positioning이 주입하는 top, left, transform은 library internal behavior로 취급한다.

불가피한 lint 예외는 가장 좁은 한 줄에 기술적 이유를 남긴다. package boundary 위반에는 escape hatch를 쓰지 않고 책임을 옮긴다.

Application handoff

제품 용어, 화면 상태와 use case가 등장하면 디자인 시스템 문서의 범위를 벗어난다. consuming application의 View와 orchestration 규칙을 따른다.
