Components

Form controls

입력·선택 component의 native semantics, validation, 접근성 계약입니다.

Form controls are split between the vendor-neutral primitive package and the composition package. The primitives own native semantics, keyboard behavior, refs, controlled/uncontrolled state, tokens, and quiet motion. Compositions own label/description/error relationships and layout; validation policy, form library, schema, and product copy stay in the consuming application.

Public catalog

Import from package roots only. Radix and other implementation types are not part of this surface.

Select is a single-value compound control. Its public parts are SelectValue, SelectTrigger, SelectContent, SelectGroup, and SelectOption; portal scroll buttons and indicators remain private.

Native controls

Label accepts native label attributes and requiredIndicator. Textarea accepts native textarea attributes, forwards its ref, and deliberately does not provide autosize or JavaScript height measurement.

Checkbox, Radio, and Switch preserve form participation (name, value, required, and disabled state) and can be either uncontrolled or controlled.

Select supports the same controlled/uncontrolled split and exposes open state callbacks when an app needs to observe it.

Select uses a portal and returns focus to its trigger after Escape or dismiss. It intentionally does not implement NativeSelect, multi-select, combobox/autocomplete, async filtering, or virtualization. Use a product/app adapter when those behaviors are required; do not add them to this primitive.

Field and composition callbacks

Field render children receive FieldControlProps; ChoiceField render children receive ChoiceControlProps. These public callback contracts keep stable IDs, disabled/required state and described-by relationships owned by the Composition.

Field supplies stable id, required, disabled, invalid, description, and error ARIA props to the control through a render callback. The message area reserves one line, so toggling an error does not move a following sibling.

ChoiceField applies the same relationship to Checkbox, Radio, or Switch and makes the visible label the click target. FormGroup provides a fieldset, legend, and optional group description.

InputField remains an aligned convenience composition for an input and password visibility action. New code should use the composition root; consumers should use the Composition package root.

Validation adapter boundary

The core packages do not depend on RHF, Zod, or product validation messages. An app adapter maps the form library field to the public control and passes validation state to Field:

The Controller, schema, option mapping, dependent-field reset, submit mutation, and error policy are app concerns. They must not become primitive props or package dependencies.

Quiet functional motion

  • Inputs, Textarea, and SelectTrigger transition semantic color, border, and focus ring with duration-fast and ease-standard.
  • Checkbox and Radio transition state color/opacity; Radio's small indicator transform is composited.
  • Switch transitions track color and thumb transform with duration-base and ease-standard; its interactive target remains at least 40px.
  • Select content uses opacity and a small transform only. Portal positioning is library behavior, not an app layout animation.
  • No bounce, overshoot, stagger, continuous decoration, frame loop, or width/height/top/left/margin/padding transition is allowed.

Every moving control exposes motion-reduce:transition-none. Select content also sets motion-reduce:duration-0, so prefers-reduced-motion: reduce removes both the transition property and its computed duration. State and keyboard behavior remain available in reduced motion.

Accessibility checklist

  • Use a visible Label/ChoiceField label or an explicit accessible name.
  • Keep label → description → error in that reading order; use the IDs supplied by Field/ChoiceField rather than duplicating them.
  • Preserve native required, disabled, name, and form value semantics.
  • Verify keyboard focus, RadioGroup roving focus, Select typeahead, Escape dismissal, and Select trigger focus restoration.
  • Keep error state on the control with aria-invalid and aria-errormessage; do not move focus or create a live announcement for every keystroke.
  • Check light/dark contrast, forced colors, visible focus, 40px touch targets, and 200%/400% reflow at narrow widths.
  • Run the real-browser and forced-colors Axe checks before release.

Verification

Behavior tests cover controlled/uncontrolled state, form participation, Select keyboard/dismiss/focus restoration, and Field relationships. Type tests preserve the public prop surface and reject vendor-private options. Storybook covers default, disabled, invalid, dark, reduced-motion, keyboard, and layout-stability states.
