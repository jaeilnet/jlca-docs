개발

기여 가이드

Token, Foundation, Primitive, Composition 변경을 올바른 package에 추가합니다.

새 코드는 먼저 컴포넌트 배치 결정을 적용한다. 현재 public package root와 실행 gate를 같은 변경에서 보존한다.

공통 절차

  1. Tokens, Foundation, Primitive, Composition 또는 생성 조건을 충족한 Capability 중 소유자를 정한다.
  2. 제품 용어가 필요하면 디자인 시스템 변경을 중단하고 Domain View로 분류한다.
  3. public props와 접근성·상태 계약을 먼저 정의한다.
  4. 실패하는 behavior test를 확인한 뒤 구현한다.
  5. semantic token만 사용한다.
  6. local fixture와 action으로 Story를 작성한다.
  7. package public export와 문서를 함께 갱신한다.
  8. dependency와 bundle side effect가 package 밖으로 전파되지 않는지 검증한다.

승인된 catalog의 Core family는 실제 제품 소비가 선행 조건이 아니다. 대신 범용 의미, native semantics, token/style ownership, 접근성, SSR, compile-time 계약, Story와 문서 gate를 모두 완성해야 한다. 제품 패턴과 Capability는 실제 소비 흐름 없이 선구현하지 않는다.

새 family는 먼저 Layout, Typography, Form, Table, Navigation, Media, Document Structure, Interactive Content 중 어떤 Web 의미 체계를 소유하는지 밝힌다. 후보 family 이름만으로 component manifest나 export를 선점하지 않는다. 외부 디자인 시스템의 category는 비교 연구에 사용할 수 있지만 JLCA taxonomy와 API의 근거가 되지 않는다.

Token 기여

  1. 필요한 semantic 의미와 light/dark 상태를 먼저 정의한다.
  2. 기존 reference scale로 표현할 수 없을 때만 새 reference token을 추가한다.
  3. component token은 반복되고 안정된 계약일 때만 추가한다.
  4. alias missing/cycle, theme parity, contrast와 generated output을 확인한다.

현재 source는 다음과 같다.

generated CSS는 직접 편집하지 않는다.

referenceTokens가 정식 public API다. deprecated primitiveTokens는 기존 consumer 호환에만 사용한다. compatibility/dark.json은 기존 Web dark palette 출력 전용이므로 신규 token을 직접 추가하거나 component에서 import하지 않는다.

Primitive 기여

  • 새 Primitive는 packages/primitives에 두고 package root로 export한다.
  • Box/Flex/Stack/Group/Container/Center/RepeatGrid/Grid/GridItem/AspectRatio spacing, radius와 color는 각각 SpaceToken, RadiusToken, semantic color role만 받는다. Container size는 BreakpointToken만 받고 RepeatGrid/Grid columns와 GridItem span은 scalar·responsive 모두 1–12만 받는다. Grid 계열의 responsive에는 base를 넣지 않고 공개 BreakpointToken만 사용한다. AspectRatio ratio는 유한한 양수만 받으며 width는 소유하지 않는다.
  • Tailwind responsive class를 prop 값으로 선택할 때는 scanner가 읽을 수 있는 완전한 literal lookup을 사용한다. `${breakpoint}:grid-cols-${columns}` 같은 동적 class 생성, matchMedia, per-instance style 주입은 금지한다.
  • native semantic element로 충분한지 먼저 확인한다.
  • 복잡한 widget은 저장소의 기존 headless 생태계를 사용한다.
  • vendor props/type을 그대로 re-export하지 않고 JLCA 공개 계약으로 감싼다.
  • keyboard, focus, disabled, open/closed와 controlled/uncontrolled behavior를 테스트한다.
  • headless behavior에 JLCA token, variant와 motion을 결합한다.
  • Typography는 Text, Title, Code, Blockquote, List, ListItem의 native 의미를 유지하고 owned style을 raw style로 우회하지 못하게 한다.
  • Table은 table, caption, colgroup, col, thead, tbody, tfoot, tr, th, td의 native 구조를 유지한다. header cell은 scope를 필수로 받고 복합 header의 id/headers/span을 보존한다.
  • 반응형 Table은 descendant를 display: block | grid | flex 또는 card로 바꾸지 않는다. overflow가 필요할 때만 accessible name을 가진 TableScrollArea를 명시적으로 조합한다.
  • sorting, selection, editing, virtualization, grid keyboard navigation과 product data behavior가 필요하면 static Table에 prop을 더하지 않고 DataGrid를 별도 설계한다.

Composition 기여

  • 실제로 둘 이상의 Primitive를 조합하는지 확인한다.
  • 이름과 props에서 제품 도메인 용어를 제거해도 의미가 유지되어야 한다.
  • Query/mutation/router/auth object 대신 display data와 intent callback을 받는다.
  • Charts, Carousel, Maps를 import하지 않는다.
  • label-error-description 연결과 복합 읽기 순서를 테스트한다.

Capability 기여

  • vendor dependency는 해당 package manifest에만 둔다.
  • vendor type과 instance를 public API에 노출하지 않는다.
  • semantic token을 vendor option으로 변환하는 adapter를 package 내부에 둔다.
  • CSS/module side effect는 이름이 드러나는 explicit entry로 제한한다.
  • vendor update, hydration, resize와 data update behavior를 테스트한다.
  • canvas/SVG 대체 콘텐츠와 keyboard/gesture fallback을 제공한다.

Chart series의 business 의미, Map marker의 제품 상태, Carousel item 내용은 Domain View가 정한다.

Storybook

  • Story는 package source 가까이에 둔다.
  • live API, QueryClient, auth/router provider, environment secret을 사용하지 않는다.
  • light/dark와 주요 interaction state를 local fixture로 표현한다.
  • Capability Story는 vendor를 실제로 사용하되 product Domain을 import하지 않는다.
  • 각 공개 component는 usage·non-usage, 상태 matrix, theme·viewport, keyboard play test, 접근성 주의와 Composition 예시를 제공한다.

운영 책임

  • package마다 상시 owner와 backup, public API·breaking change 승인자를 둔다.
  • Changesets가 version과 changelog 변경을 기록한다.
  • package build는 publish 대상 dist를 완성하고 packed artifact smoke test를 통과한다.
  • 배포 순서와 rollback 정책을 release workflow와 함께 유지한다.

변경 전 checklist

  • 제품 의미가 없는 디자인 시스템 책임인지 확인했다.
  • Tokens와 Foundation을 중복 정의하지 않았다.
  • Primitive/Composition/Capability 의존 방향을 지켰다.
  • public API가 vendor에 독립적이다.
  • light/dark, keyboard와 접근성 상태를 확인했다.
  • Story가 application provider 없이 동작한다.
  • 구현 완료 family와 candidate 상태를 문서에서 정확히 구분했다.
  • 새 semantic family라면 native, token, 접근성, SSR, type, Story, docs와 dependency gate를 모두 닫았다.
