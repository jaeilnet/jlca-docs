재검증 체크리스트

Core package, 공식 문서와 clean deployment build를 독립적으로 확인합니다.

이 절차는 현재 독립 저장소의 public package, architecture, Storybook과 공식 문서를 재검증한다. 각 command, exit code, test/violation count와 warning/error 귀속을 기록한다. 실패를 발견하면 diff와 merge base에서 재현 여부를 먼저 판정한다.

0. 환경

기대값은 Node 24.x, pnpm 9.12.1, frozen install 성공이다. 시작 status가 clean이 아니면 기존 변경을 보존하고 검증으로 생긴 delta와 구분한다.

1. Package와 public entry

각각 packages/tokens, packages/foundation, packages/primitives, packages/compositions를 가리켜야 한다. manifest exports는 Tokens runtime와 web.css, Foundation styles.css, Primitives/Compositions root runtime와 type을 dist artifact로 공개해야 한다.

packed artifact contract는 실제 tarball을 설치해 root runtime/type/CSS export와 downstream compile을 확인한다. source deep import가 pack 결과에 새어 나오면 실패해야 한다.

2. Token 결정성과 platform neutrality

tokens:check는 generator를 실행한 뒤 generated CSS drift와 contrast를 검증한다. TSX/React 검색은 0건이어야 한다. 실행 뒤 예상하지 않은 tracked delta가 생기면 임의 cleanup하지 않는다.

3. Architecture mutation contract

Architecture contract는 다음을 실제 fixture나 AST 입력으로 검증한다.

  • package source의 application import와 public boundary 우회 차단
  • Foundation의 component/runtime 역방향 dependency 차단
  • Primitive의 Composition import와 Composition의 선택적 Capability import 차단
  • hardcoded color, arbitrary z-index와 raw transition lint mutation
  • Storybook의 network, environment secret와 application provider 의존 차단
  • root barrel의 SSR-safe module evaluation

fixture를 쓰는 test는 자신의 scoped temporary directory만 정리해야 한다. 전후 status가 다르면 현재 경로를 보존해 보고한다.

4. 실제 lint와 dependency 방향

ESLint error는 0건이어야 한다. typecheck는 Turbo graph가 upstream package build를 먼저 실행하고 모든 package public type surface를 검사해야 한다. 검증을 통과시키려고 rule, type test나 exclusion을 약화하지 않는다.

5. Storybook purity와 production build

Storybook은 Foundation CSS와 package source만으로 정적 build해야 한다. Story implementation에는 direct network, environment secret, application API/auth/provider import가 없어야 한다. pnpm build는 Tokens → Foundation/Primitives → Compositions의 graph와 publish 대상 dist를 완성한다.

6. Full test와 package artifact

최종 보고에는 test file/test count, pass/fail 수와 pack smoke test 결과를 포함한다. package artifact는 tracked source나 secret을 포함하지 않고 public exports의 target 파일을 모두 포함해야 한다.

7. Package purity direct scan

구현 import 위반은 0건이어야 한다. test string이나 문서 예시가 출력되면 실제 import인지 구분한다. package-private 상대 import는 허용하지만 다른 package의 source tree로 들어가는 physical deep import는 허용하지 않는다.

8. 공식 문서와 credential audit

공식 문서는 여섯 navigation section 순서, 9개 guide migration inventory, Core public 계약, 독립 경로와 tokenless registry 인증을 검증한다. 모든 _authToken assignment는 ${NODE_AUTH_TOKEN}만 값으로 사용해야 한다.

9. Clean app-root docs build

Foundation dist와 docs .next가 없는 clean checkout 조건을 만든 뒤 docs app의 자체 command를 실행한다.

prebuild가 Turbo를 repository root에서 실행해 Tokens와 Foundation의 gitignored dist를 먼저 만들고, 이어서 Next production build가 완료되어야 한다. root orchestration도 별도로 확인한다.

두 command 중 app-root command를 bare next build로 바꾸면 clean deployment가 실패하므로 conventional build와 dependency graph contract를 함께 유지한다.

10. 최종 integrity

최종 status는 시작 status와 같아야 한다. build가 만든 .next, .source, .turbo와 package dist는 기존 상태를 구분해 정리한다. 예상하지 않은 파일은 삭제하지 말고 상태와 경로를 보존해 보고한다.

실패 귀속

  1. 실패 파일이 현재 package/config/docs diff에 포함되는지 확인한다.
  2. architecture/lint error라면 Core 회귀로 우선 조사한다.
  3. 광역 typecheck/test failure는 base commit에서 동일하게 재현되는지 격리 확인한다.
  4. base와 head의 오류가 동일하면 기존 부채로 기록하고 이 작업에서 임의 수정하지 않는다.
  5. head에만 생긴 오류는 새 regression으로 기록한다.

기여 가이드

Token, Foundation, Primitive, Composition 변경을 올바른 package에 추가합니다.
