설치와 인증

GitHub Packages에서 Core 패키지를 안전하게 설치합니다.

JLCA Core 패키지는 GitHub Packages에 배포됩니다. 저장소나 CI의 환경 변수로 인증하고, 문서나 설정 파일에 실제 토큰을 기록하지 않습니다.

.npmrc 설정

프로젝트의 .npmrc에 scope와 registry를 선언합니다.

로컬 셸 또는 CI secret store에 NODE_AUTH_TOKEN을 제공합니다. 토큰 값은 커밋, 로그, 스크린샷에 남기지 않습니다. 로컬 GitHub CLI credential을 사용할 때는 먼저 package read scope를 승인하고 현재 shell에만 주입합니다.

classic PAT을 사용하는 경우 read:packages scope와 이 private package에 연결된 repository 접근 권한이 필요합니다. 조직에서 SSO를 사용하면 PAT도 별도로 승인해야 합니다. GitHub Actions에서는 package가 접근을 허용한 repository의 GITHUB_TOKEN을 NODE_AUTH_TOKEN으로 해당 설치 step에만 전달합니다.

Core 설치

현재 검증된 조합은 위 네 exact version입니다. dependency를 선언한 뒤 pnpm install을 실행합니다.

Foundation과 component utility 적용

애플리케이션 bootstrap에서 한 번만 Foundation CSS를 불러옵니다. Tailwind CSS v4가 설치된 component bundle의 utility literal을 생성하도록 project root CSS entry에 두 package dist source를 함께 선언합니다.

@source 경로는 CSS entry의 위치를 기준으로 합니다. CSS 파일이 src/ 아래에 있으면 ../node_modules/...처럼 실제 상대 경로를 사용합니다. Foundation만 import하면 token graph는 생기지만 Link, SkipLink, Breadcrumb, Pagination을 포함한 component utility는 생성되지 않습니다.

컴포넌트 package는 Foundation을 다시 import하지 않습니다. 제품 앱이 semantic token 환경과 installed package scan을 한 번 설치하고, 각 component는 그 계약을 소비합니다.

연결 상태 확인

토큰 자체를 출력하지 않고 package metadata를 조회합니다. 아래 명령은 성공하면 정확히 0.1.0을 반환해야 합니다.

나머지 현재 버전도 같은 방식으로 확인할 수 있습니다.

GitHub 연결과 visibility는 package API에서 확인합니다. 사용자 credential 응답의 visibility는 private, repository.full_name은 jaeilnet/jlca-design-system이어야 합니다. 권한이 제한된 Actions GITHUB_TOKEN 응답은 repository를 null로 생략할 수 있습니다. 이 경우 CI가 증명하는 것은 package 접근·설치 가능성뿐이며 repository linkage는 관측 불가 상태입니다.

네 package의 실제 GitHub Packages linkage는 repository.full_name을 관측할 수 있는 최소 read:packages credential로 별도 strict audit을 실행합니다. 현재 GitHub CLI credential을 shell 환경에만 주입한 뒤 다음 명령이 verified-package-linkages=4를 반환해야 합니다.

pnpm view의 repository.url은 배포된 package.json의 self-declared provenance입니다. package version과 artifact provenance를 확인하는 보조 증거이며 GitHub Packages의 실제 repository linkage를 대체하지 않습니다.

오류 진단

  • 401 Unauthorized: NODE_AUTH_TOKEN이 비어 있거나 만료됐거나 .npmrc의 ${NODE_AUTH_TOKEN} 참조가 설치 process에 전달되지 않았습니다. 환경 변수 존재 여부만 확인하고 값을 출력하지 않은 채 다시 주입합니다.
  • 403 Forbidden: credential은 인식됐지만 read:packages scope, SSO 승인 또는 package repository 접근 권한이 없습니다. scope와 package access를 승인한 후 health check를 다시 실행합니다.
  • 404 Not Found: @jaeilnet scope mapping, package 이름·버전 또는 package에 부여된 repository access가 잘못됐을 수 있습니다. .npmrc registry와 위 exact version을 먼저 확인합니다. private package는 권한 부족도 404로 보일 수 있습니다.

진단 중에도 literal token을 .npmrc, command argument, issue, CI log에 붙여 넣지 않습니다. 인증 값을 바꾼 뒤에는 pnpm view @jaeilnet/design-tokens@0.1.0 version부터 다시 실행합니다.
