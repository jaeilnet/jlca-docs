Core 로드맵

현재 완료 상태와 다음 semantic family·capability의 진입 조건을 구분합니다.

목표는 네 Core package를 독립적으로 build, test, version, publish하고 제품 전용 View를 Core 밖에 두는 것이다.

CURRENT

  • @jaeilnet/design-tokens: reference/semantic/component source, typed runtime, generated Web CSS
  • @jaeilnet/design-foundation: reset, base, token binding과 light/dark bootstrap CSS
  • @jaeilnet/design-primitives: Layout, Typography, Form, Table과 Navigation semantic family
  • @jaeilnet/design-compositions: InputField, Field, ChoiceField, FormGroup, Breadcrumb, Pagination
  • Storybook, architecture, package artifact와 docs contract는 독립 저장소에서 실행
  • Changesets와 package publish workflow 구성

CURRENT는 동작하는 기준선이지 존재하지 않는 family나 Capability 승인이 아니다.

성공 지표

Core 품질은 catalog·public API·token·접근성·Story·SSR·dependency·bundle·문서 동기화로 측정한다. Downstream 결과는 구현 리드타임, 중복 UI·스타일, public root 채택률, Legacy 제거율, UI 회귀와 접근성 위반 수로 측정한다. 각 이관 workstream은 이 지표 중 무엇을 움직이는지 기록한다.

APPROVED CORE와 CONDITIONAL CAPABILITY

  • Core의 각 디렉터리는 독립 package다.
  • Composite는 Composition으로 이름을 통일한다.
  • 제품 전용 UI package는 제거한다.
  • 제품 전용 순수 View는 app Domain/Shell views로 이동한다.
  • charts, carousel, maps는 실제 소비자, vendor 격리, vendor-neutral API, SSR/client와 접근성 fallback 계약을 충족한 경우에만 하나씩 만든다.
  • 생성된 Capability의 vendor dependency와 CSS side effect는 해당 package에만 남긴다.

이관 순서

1. Token과 theme 재정비

  • 기존 orange primary 기준선 고정
  • primitive source를 reference로 이관하고 호환 alias 유지
  • light/dark semantic path parity와 dark compatibility bridge 분리
  • Box/Stack용 spacing/radius reference scale 추가
  • action/content/surface/border/feedback/focus semantic state set 확정
  • contrast gate 추가
  • Chart/Map runtime token adapter 계약 확정
  • Typography text/title/code recipe를 theme-independent component token으로 추가
  • 이후에도 반복되고 독립 진화하는 component token만 선별 추가

2. Foundation 분리

  • reset, font, base, theme selector와 styling binding을 독립 package로 이동
  • 앱과 Storybook이 Foundation을 한 번만 import하도록 bootstrap 고정
  • token source 중복 정의 제거
  • legacy Swiper CSS를 Foundation 밖의 좁은 호환 entry로 격리

3. Branded Primitives 분리

  • typed spacing/radius/semantic color를 사용하는 polymorphic Box 구현
  • token gap과 flex alignment를 제어하는 Stack 구현
  • 독립 package manifest, public root export, Storybook source와 boundary gate 추가
  • Primitive public API와 vendor-private 경계 확정
  • Button에 headless composition, semantic token, variant, motion 결합
  • Input의 native contract와 semantic field 상태를 독립 package로 이관
  • Mantine-inspired 범용 Flex와 간결한 horizontal Group 구현
  • Container/Center를 구현하고 Header/Footer의 legacy page-container 소비 흐름 이관
  • JLCA 언어로 재설계한 RepeatGrid를 구현하고 Owner dashboard의 고정 3열 통계 이관
  • Grid·GridItem을 구현하고 추천 화면의 모바일 7:3 액션 소비 흐름 이관
  • AspectRatio를 구현하고 판매점 카드의 4:3·5:6 및 adapter의 1:1 이미지 비율 계약 이관
  • 실제 spacer 소비자가 없는 Space는 gap·margin과 중복되므로 선구현하지 않기로 결정
  • per-instance style 주입 없이 정적 literal class map을 사용하는 responsive Grid columns/span 계약 추가
  • Text, Title, Code, Blockquote, List, ListItem Typography Core family와 token·semantic·SSR·type·Story 계약 추가
  • Table semantic family의 native anatomy, component token, style ownership, accessibility, SSR, type, Story와 문서 검증 완료
  • responsive spacing·Flex 속성·offset·order·row span의 실제 소비자를 확인한 뒤 범위별 계약 설계
  • 나머지 interactive Primitive에 같은 계약 적용
  • 기존 web/src/primitives를 독립 package로 이동

4. Compositions 분리

  • 독립 @jaeilnet/design-compositions package와 dependency gate 추가
  • InputField를 Box/Stack/Group/Input/Button 조합으로 이관하고 raw div 금지
  • Field, ChoiceField, FormGroup을 구현하고 대표 Form 소비자 4개 이관
  • 기존 Composite를 범용 Composition과 제품 Domain View로 재분류
  • 둘 이상의 Primitive 조합만 package에 유지
  • 제품 용어와 application I/O 제거

5. Capability 분리

  • 생성 조건을 충족한 실제 사용자 흐름 하나를 먼저 선택
  • Chart.js → Charts, Swiper → Carousel, map SDK → Maps 중 선택된 하나만 이관
  • 각 vendor dependency, public API, update/hydration test 격리
  • vendor-neutral data/event/command, SSR/client boundary와 접근성 대체 경험을 선행 계약

6. Application handoff

  • 디자인 시스템은 제품 전용 View를 소유하지 않는다.
  • 범용 최소 UI는 Primitive, 범용 조합은 Composition으로 분류한다.
  • vendor 기술은 생성 조건을 갖춘 선택적 Capability로 격리한다.
  • 화면 의미, data policy와 route orchestration은 consuming application이 소유한다.

횡단 Gate와 문서 전환

  • 모든 이관 단계와 병행
  • package별 exports, ESLint와 dependency-cruiser rule 적용
  • package별 Storybook source와 test ownership 정리
  • app의 vendor direct import와 package deep import 차단
  • revalidation prompt를 TARGET 기준으로 교체

7. Navigation semantic family

  • 상태: 구현 완료 · package root export 제공
  • public API 후보, native mapping, token, 접근성, SSR, Story와 경계 기록
  • Link, Navigation, NavigationList, NavigationItem, SkipLink 구현
  • Breadcrumb composition 구현
  • Pagination composition 구현
  • Storybook, architecture와 실제 브라우저 통합 검증
  • 세부 계약은 Navigation을 따른다.

Core 완료 기준

  • 새 Core family는 실제 제품 소비와 무관하게 catalog 완결성, native semantics, token/style ownership, 접근성, SSR, type, Story, 문서와 dependency gate를 모두 통과한다.
  • 네 Core package가 각각 독립 manifest와 public exports를 가진다.
  • 제품 전용 View가 Core package에 없다.
  • 제품 의미를 가진 순수 View는 app domain/shell에 있다.
  • capability vendor dependency가 core package에 없다.
  • light/dark가 semantic alias로 동작한다.
  • app/Storybook이 Foundation을 한 번만 설치한다.
  • 디자인 시스템의 app/Next/Domain import와 앱의 vendor UI 직접 import가 0건이다.
  • architecture, lint, typecheck, Storybook과 주요 회귀 test가 통과한다.

Capability는 Core 완료 조건이 아니다. 제품 패턴과 Capability는 실제 소비자가 생성 조건이며, 생성된 Capability는 실제 소비자 이관, vendor direct import 0건, SSR/hydration, 접근성 fallback과 bundle budget을 별도 완료 조건으로 가진다.

Section/Page/Domain migration의 세부 로드맵은 consuming application architecture가 소유한다.

동기화 Trigger

  • Architecture 또는 package 생성 조건이 승인·변경됐을 때
  • Public API, theme·접근성 계약 또는 호환 제거 기준이 바뀌었을 때
  • Workstream 상태가 진입·완료·중단으로 바뀌었을 때
  • 작업 브랜치 snapshot을 갱신할 때
