Token 카탈로그

JLCA의 디자인 결정을 reference, semantic, component 계층으로 사용합니다.

@jaeilnet/design-tokens는 브랜드 디자인 결정의 유일한 정본이다. Foundation과 모든 component/capability package는 이 값을 소비하며 별도 palette를 만들지 않는다.

목표 계층

단계예역할
Reference/Globalcolor.blue.600, space.4, radius.mdraw palette와 scale
Semantic/Aliascolor.action.primary.background, color.surface.default, color.content.muted사용 의미와 theme 계약
Componenttypography.text.md.fontSize, table.density.compact.paddingBlock반복되고 독립 진화하는 component 계약

컴포넌트는 가능한 한 semantic token을 사용한다. component token은 같은 조합이 반복되거나 component가 global semantic과 다른 생명주기를 가져야 할 때만 추가한다.

Source

reference, semantic, component/typography.json, component/table.json이 현재 source에 적용됐다. component token은 반복되고 독립 진화하는 계약이 확인될 때만 추가한다.

현재 semantic color는 action, content, surface, border, feedback, focus 역할을 Light/Dark 동일 경로로 제공한다. content에는 primary | secondary | muted | inverse | accent | success | warning | danger | info가 있으며 기본 surface 위 text pair는 4.5:1, focus indicator는 3:1 contrast gate를 통과해야 한다.

Typography reference는 fontFamily.sans, fontFamily.mono, 기존 font size/weight/line-height/letter-spacing scale을 제공한다. component recipe는 --typography-text-*, --typography-title-*, --typography-code-* CSS 변수로 생성되고 Foundation의 기본 font는 --font-family-sans를 사용한다. 기존 .text-heading-*, .typo-body*, .typo-caption* utility는 Legacy 호환 값으로 유지한다.

Table component recipe는 다음 열 개의 generated variable을 제공한다.

compact/default/relaxed density는 reference space에 alias되고 font size, header weight와 line height는 typography reference에 alias된다. Table의 surface, content, border와 focus color는 component token으로 복제하지 않고 기존 semantic color 변수를 직접 소비하므로 light/dark 경로가 같다.

Primary와 theme 설계

현재 승인된 Primary는 기존 orange palette다.

  • light primary.500: oklch(0.68 0.23 45)
  • dark compatibility primary.500: oklch(0.75 0.2 45)

색상 교체보다 먼저 semantic state set과 소비 계약을 완성한다.

Primary color는 palette의 한 값이 아니라 다음 semantic set으로 검증한다.

  • primary surface와 on-primary content
  • hover, pressed, selected, disabled
  • focus ring과 outline
  • primary container와 on-primary-container
  • light/dark 각각의 contrast
  • 인접 surface, border, text token과의 조화

light/dark mode는 component 분기문이 아니라 semantic alias 교체로 동작한다.

컴포넌트에서 isDark ? blue400 : blue600처럼 raw theme 값을 선택하지 않는다.

Foundation은 :root에 light semantic variable을 설치하고 [data-theme='dark']에서 같은 semantic path의 값을 교체한다.

Foundation handoff

Tokens가 무엇을 사용할지 결정한다면 Foundation은 그 결정을 Web에서 어떻게 설치할지 책임진다.

  • Tokens: JSON/typed data, alias resolution, generated CSS variable data
  • Foundation: selector, reset, font, color-scheme, theme bootstrap, styling engine binding

Tokens source에는 CSS selector, Tailwind directive, React provider와 앱 route를 넣지 않는다. Foundation은 token 값을 재정의하지 않는다.

Capability token

Chart/Map처럼 JavaScript runtime 값이 필요한 경우에도 raw hex를 package source에 넣지 않는다.

  • CSS custom property를 getComputedStyle로 읽거나
  • @jaeilnet/design-tokens의 typed resolved value를 사용한다.

제품별 series·marker 의미는 Domain View가 semantic role로 매핑하고 Capability는 해당 role을 JLCA token으로 표현한다.

Layout scale

Box, Flex, Stack, Group, Container, Center, RepeatGrid, Grid, GridItem, AspectRatio와 이후 layout Primitive의 spacing, radius, breakpoint는 임의 숫자 대신 다음 reference scale을 사용한다.

  • Space: 0, 0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 6, 8, 10, 12, 16, 20, 24
  • Radius: none, xs, sm, md, lg, xl, 2xl, 3xl, full
  • Breakpoint: mobile, mobile.s, tablet, laptop, laptop.lg, laptop.xl

Web에서는 각각 --space-*, --radius-*, --breakpoint-*로 생성된다. space.0.5의 CSS 이름은 --space-0-5이고 laptop.lg의 CSS 이름은 --breakpoint-laptop-lg다. Container의 scalar size는 BreakpointToken을 max-width로 사용한다. Grid 계열의 responsive key는 같은 BreakpointToken을 mobile-first min-width variant로 사용하며 dotted token은 Tailwind variant에서 hyphen으로 바꾼다. AspectRatio의 unitless 양수 ratio는 미디어 고유 비율이므로 reference token으로 제한하지 않는다.

현재와 목표

현재 source:

TypeScript의 정식 runtime API는 referenceTokens, semanticTokens, componentTokens다. primitiveTokens와 PrimitiveTokenPath는 기존 consumer를 위한 deprecated alias이며 신규 코드에서 사용하지 않는다.

compatibility/dark.json은 기존 raw palette class의 dark 동작을 보존하는 출력 전용 bridge다. package public API로 export하지 않으며 새 component token의 source로 사용하지 않는다.

Application과 Storybook은 @jaeilnet/design-foundation/styles.css를 bootstrap에서 직접 적용한다. Foundation은 내부에서 token Web CSS를 한 번 설치한다. Tailwind CSS v4 application은 별도로 installed Primitives와 Compositions dist를 @source에 등록해 component utility를 생성한다. 구체적인 설치 block은 설치와 인증을 따른다.

변경 규칙

  1. 기존 semantic token으로 표현 가능한지 먼저 확인한다.
  2. 새 reference 값보다 먼저 필요한 semantic 의미와 상태를 정의한다.
  3. light/dark를 같은 변경에서 완성한다.
  4. alias missing/cycle, 생성 결정성, contrast를 검증한다.
  5. generated file은 직접 편집하지 않는다.
  6. 제거·rename은 public token migration과 deprecation 계획을 함께 작성한다.
  7. 신규 component는 semantic token을 사용한다. reference token 직접 사용은 token 설계와 capability adapter로 제한한다.
